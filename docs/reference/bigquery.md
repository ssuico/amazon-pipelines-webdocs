# BigQuery & Datasets

How Amazon Pipelines stores report data in Google BigQuery.

## Datasets

| Env var | Default | Contents |
|---------|---------|----------|
| `BIGQUERY_DATASET` | `amz_sp_api_reports_v1` | SP report tables, `report_status`, `account_details` |
| `BIGQUERY_ADS_DATASET` | `amz_ads_api_reports_v1` | Ads report tables, `ads_report_status` |
| `GCP_PROJECT_ID` | `research-analytics-v1` | GCP project |

## Table naming

### SP reports

Account-prefixed: `{AccountName}_{table_name}`

Examples: `OE_orders`, `Bumbleride_sales_and_traffic`, `ArmsReach_inventory`

Generated by `BigQueryClient._get_full_table_name(account_name=...)`.

### Ads reports

Runtime uses **unprefixed** table names: `SP_campaign_table`, `SB_targeting_table`, `SD_campaign_timeseries_table`, etc.

The migration script `scripts/migrate_ads_tables.py` may use a legacy `{account}_` prefix — verify your environment.

### Status and metadata tables

| Table | Dataset | Prefix |
|-------|---------|--------|
| `report_status` | SP | None |
| `account_details` | SP | None |
| `ads_report_status` | Ads | None |

## BigQueryClient

Location: `app/services/sp/bigquery_client.py`

### Initialization

```python
from app.services.sp.bigquery_client import BigQueryClient, get_bq_client

# SP dataset (default)
client = BigQueryClient()

# Ads dataset
client = BigQueryClient(dataset_name=settings.bigquery_ads_dataset)
```

Requires `GOOGLE_APPLICATION_CREDENTIALS` pointing to a service account JSON key (local) or Cloud Run default credentials (production).

### Key methods

| Method | Purpose |
|--------|---------|
| `upsert_report_data(df, table_name, schema, merge_columns, account_name)` | SP report MERGE upsert |
| `upsert_ads_report_data(df, table_name, schema, merge_columns)` | Ads report MERGE upsert |
| `get_last_ads_report_date(table_name)` | Max date for incremental Ads loading |
| `run_query(sql, params)` | Parameterized query execution |
| `ensure_table_exists(table_name, schema, account_name)` | Create table if missing |

Removed methods (per design-log 2026-05-15): `insert_data`, `insert_dataframe` — all writes go through upsert.

## Upsert pattern

Both SP and Ads pipelines use staging + MERGE:

1. Convert DataFrame column types to match BigQuery schema
2. Load DataFrame into a temporary staging table
3. Execute MERGE: staging → target ON merge columns
   - WHEN MATCHED → UPDATE non-key columns
   - WHEN NOT MATCHED → INSERT
4. Drop staging table

Merge columns are defined per report type:

- SP: `AccountConfig.MERGE_COLUMNS` and schema configs
- Ads: `GROUPING` / `MERGE_COLUMNS` in schema classes

## Schema-driven configuration

SP reports use `ReportSchemaConfig` (`app/schemas/sp/base_report_schema.py`):

- `bq_schema` — BigQuery field definitions
- `column_mappings` — source → target column renames
- `merge_columns` — unique keys for MERGE
- `aggregations` — duplicate row handling

Registry: `get_report_schema(report_type_key)` from `app/schemas/sp/report_registry.py`

Ads reports use schema classes in `app/schemas/ads/reports/`.

## Setup

### Prerequisites

- Google Cloud Project with BigQuery API enabled
- Service account with BigQuery Data Editor + Job User roles
- Service account JSON key (local development)

### Create datasets

```sql
CREATE SCHEMA IF NOT EXISTS amz_sp_api_reports_v1
OPTIONS (location = 'US', description = 'Amazon SP-API Reports');

CREATE SCHEMA IF NOT EXISTS amz_ads_api_reports_v1
OPTIONS (location = 'US', description = 'Amazon Ads API Reports');
```

Tables are created automatically on first upsert if they do not exist.

### Seed account metadata

```bash
python scripts/create_account_details_table.py --seed
```

## Programmatic example

```python
import asyncio
from app.services.sp.amazon_sp import AmazonSPService

async def load_and_upsert():
    sp = AmazonSPService(account_name="OE")
    result = await sp.process_and_upsert_report(
        report_type_key="orders",
        load_last_day=True,
    )
    print(f"Rows upserted: {result.get('rows_upserted')}")

asyncio.run(load_and_upsert())
```

The service handles schema lookup, transformation, and BigQuery upsert internally.
